SC-900 cheat sheet 1/4 — Security and identity concepts

One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Zero Trust

PrincipleWhat it means
Verify explicitlyAuthenticate and authorise every request using identity, device, location, data, and risk signals.
Least privilegeMinimum access for the shortest time, with just-in-time elevation.
Assume breachDesign as if an attacker is inside: segment, monitor, and limit blast radius.

Zero Trust is a strategy, not a product. It replaces the trusted network with per-request decisions.

Defence in depth

LayerExamples
PhysicalBadges, guards, locks, cameras, locked racks
IdentityMFA, Conditional Access, PIM
PerimeterFirewall, DDoS protection, WAF
NetworkSegmentation, NSGs, encryption in transit
ComputePatching, hardening, endpoint protection
ApplicationSecure code, input validation, app authentication
DataEncryption, classification, access control, backup

Layers are independent. Data is the centre; every other layer protects it.

CIA triad

ElementQuestion and controls
ConfidentialityWho may read it? Encryption, access control, classification.
IntegrityIs it unaltered? Hashing, signatures, version control, audit.
AvailabilityCan I reach it? Redundancy, zones, backups, DDoS protection.

Core terms

TermMeaning
AuthenticationProves who or what is connecting.
AuthorisationDecides what that identity may do.
AccountingRecords what happened in audit logs.
Non-repudiationCannot credibly deny an action: signatures, tamper-evident logs.
ThreatSomething that could cause harm.
VulnerabilityA weakness that could be exploited.
RiskLikelihood × impact; used to prioritise.

Encryption, hashing, PKI

ConceptKey facts
SymmetricOne key encrypts and decrypts; fast; bulk data.
AsymmetricPublic and private key pair; slower; key exchange and signing.
At restStored data: disk, database, backup.
In transitMoving data: TLS, HTTPS, VPN.
HashingOne-way fixed-length digest; integrity; salt for passwords.
Digital signatureHash signed with a private key; origin and integrity.
PKI and certificatesA certificate authority binds a public key to an identity.

Hashing is one-way; encryption is reversible with the key.

Threat types

ThreatDescription
VirusAttaches to a file; spreads when the file is opened.
WormSelf-replicates across networks with no user action.
TrojanDisguised as legitimate software; needs a user to run it.
RansomwareEncrypts or steals data and demands payment; backups are the recovery.
PhishingImpersonates a trusted sender. Spear phishing is targeted; smishing is SMS.
DDoSMany sources flood a service; an availability attack.
Brute forceMany password attempts against one account.
Credential stuffingReuses leaked credentials from another site; MFA breaks it.
Privilege escalationRaises the attacker level of access.
Lateral movementMoves from one system to another.
Social engineeringManipulates a person into breaking procedure.

Shared responsibility

LayerIaaSPaaSSaaS

Guest OS and runtimeCustomerMicrosoftMicrosoft
Application codeCustomerCustomerMicrosoft
Data, identities, accessCustomerCustomerCustomer

Exam traps

  • Zero Trust means verify everything, not trust nothing.
  • Defence in depth is independent layers, not one strong control.
  • Encryption hides data; hashing proves it was not changed.
  • MFA needs two different factor categories.
  • A firewall does not stop a stolen credential; identity controls do.

SC-900 cheat sheet 2/4 — Identity and access management

One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Microsoft Entra ID

ConceptWhat to remember
TenantDedicated directory for one organisation. Identity boundary; can hold many subscriptions.
Security groupAssigns permissions. No collaboration workload.
Microsoft 365 groupShared mailbox, calendar, SharePoint site, and Teams team.
Dynamic groupMembership from an attribute rule. Requires P1.
Guest (B2B)Partner invited into the tenant; authenticates at home.
External ID (B2C)Consumer identity for public apps; customers, not partners.
Hybrid identityOn-premises AD synchronised with Microsoft Entra Connect.

Hybrid sign-in

OptionHow it validates
Password hash syncEntra ID checks a hash of the on-premises hash; simplest.
Pass-through authAgents validate against on-premises AD in real time.
Federation (AD FS)On-premises server issues claims.
Seamless SSOKerberos signs in domain-joined devices automatically.

Authentication

MethodFactor and note
PasswordKnow. Weakest; reuse and phishing.
Authenticator appHave. Common second factor.
SMS or voiceHave. Convenient but interceptable.
FIDO2 keyHave. Phishing-resistant; bound to site origin.
Windows HelloDevice-bound key plus PIN or biometric; TPM-protected.
Temporary Access PassTime-limited onboarding or recovery code.
TermMeaning
MFATwo or more factors from different categories: know, have, are.
PasswordlessWHfB, Authenticator phone sign-in, or FIDO2. No password.
SSPRSelf-service reset after proof of identity; writeback extends to AD.
Password ProtectionBlocks weak and banned passwords, including a custom list.

Conditional Access

PartExamples
AssignmentsUsers or groups, cloud apps, workload identities.
ConditionsUser or sign-in risk, location, device platform and state, client app.
Grant controlsBlock, MFA, compliant or hybrid device, approved app, password change.
Session controlsSign-in frequency, browser persistence, app restrictions, Cloud Apps proxy.

CA controls how a sign-in proceeds; it does not grant resource permissions. Requires P1.

Identity Protection

RiskMeaning and response
User riskCredentials probably compromised; require a password change.
Sign-in riskThis attempt looks anomalous; require MFA.

Identity Protection detects risk; Conditional Access enforces the response. Requires P2.

Access control

CapabilityPurpose
Entra rolesDirectory objects: users, groups, apps, identity policy.
Azure RBACAzure resources; scope inherits downward.
Administrative unitsScope an administrator to a subset of users, groups, or devices.
PIMEligible, time-bound role activation with approval, MFA, and audit. P2.

Governance

CapabilityWhat it does
Access reviewsRecurring recertification of access, including guests.
Entitlement managementAccess packages bundle resources with request, approval, and expiry.
Lifecycle workflowsAutomate joiner, mover, and leaver tasks.
Cross-tenant settingsControl B2B collaboration and trust partner MFA or device claims.

SSO protocols

ProtocolRemember
SAML 2.0XML assertions for enterprise SSO.
OpenID ConnectAuthentication on OAuth 2.0; returns an ID token.
OAuth 2.0Delegated authorisation; returns an access token.
FederationTrust another provider's assertions.

Exam traps

  • Guest equals B2B partner; customer equals External ID.
  • Dynamic groups use attributes and need P1.
  • MFA needs different categories, not two passwords.
  • SSPR recovers an account; PIM elevates a role.
  • Conditional Access needs P1; PIM, Identity Protection, and governance need P2.

Secure Score and comparisons

PairDistinction
Microsoft Secure ScoreMicrosoft 365 posture percentage; improvement actions raise it.
XDR vs SentinelNative Microsoft correlation vs cross-platform SIEM and SOAR.

Exam traps

  • All Defender products feed XDR; Sentinel sits above and takes third-party data.
  • Cloud Discovery uses traffic logs; app connectors use APIs.
  • Identity sensors go on domain controllers, not laptops.
  • Secure Score is posture, not attack volume.
  • VMs and storage equals Defender for Cloud; unmanaged SaaS equals Cloud Apps.

Exam traps

  • A sensitivity label does not set retention.
  • DLP can block sharing; a retention label cannot.
  • An eDiscovery hold survives user deletion.
  • Long audit retention needs Audit Premium.
  • Compliance Manager scores controls, not incidents.
